# AGENTS.md — @trdlabs/engine

Репозиторий входит в экосистему `trdlabs`. Кросс-репозиторные вопросы — архитектура и границы,
контракты API / MCP / SDK, раскатка и миграции — ведутся из `../control-center`: начинать с
[`../control-center/AGENTS.md`](../control-center/AGENTS.md). Он несёт канонический порядок
чтения и указывает на `repos.yaml` и на инвентарь этого репозитория под `repos/`.

Если `../control-center` рядом нет (отдельный клон) — пользоваться локальными документами.

## Что это

Одно **детерминированное ядро исполнения**: решение → риск → отложенная заявка → исполнение →
портфель → канонический след. Общее для `backtester` и `platform`, чтобы связка «стратегия +
риск-профиль + модель реальности» вела себя одинаково в бэктесте, реплее, бумаге и живой
торговле — с точностью до **объявленных** моделей реальности.

Пакет публичный, `@trdlabs/engine` на npm с provenance. **Текущую версию смотреть в реестре npm,
а не здесь** — номер в прозе уже протухал однажды.

## Стек

TypeScript (ESM), `decimal.js` для денег, `@trdlabs/sdk` как единственная внешняя зависимость.
Тесты — vitest. Раскладка `src/`: `actor`, `contract`, `core`, `determinism`, `reality`, `trace`.

## Команды

```bash
pnpm install --frozen-lockfile
pnpm typecheck            # tsc --noEmit
pnpm test                 # vitest run
pnpm build                # tsc -p tsconfig.build.json
```

Гейты, которые гоняет CI сверх этого, — их падение блокирует вливание:

```bash
pnpm gate:determinism     # детерминизм ядра
pnpm gate:tapes           # целостность лент
pnpm verify:package       # форма публикуемого пакета
pnpm verify:workflows     # согласованность workflow
pnpm release:preflight    # версия пригодна к публикации
```

## Правила для агента

- Ядро **детерминировано**: недетерминизм (время, случайность, порядок обхода map) сюда не
  добавляется. На это стоит `gate:determinism`, и обезвредить его — не способ починить тест.
- Деньги — только через `decimal.js`, без `number` на денежных путях.
- Отличия поведения от реальности объявляются **моделью реальности**, а не прячутся в ядре.
- Новый страж требует мутационного доказательства: обезвредить, убедиться, что краснеет, откатить.

## Gortex — граф вместо чтения файлов

Инструменты Gortex MCP предпочитать чтению файлов. Их перечень и порядок вызовов **впрыскивает
сам сервер** в начале каждой сессии — здесь он не повторяется. Повторённый, он протухает: до
2026-08-21 тут перечислялись `smart_context`, `verify_change`, `batch_edit`, `check_guards`,
`search_symbols` и ещё десяток имён, которых в поверхности `facade-v1` уже нет.

**Калибровка, которой у сервера нет: граф сужает область, исходник подтверждает поведение.**
Граф говорит, ГДЕ логика и ЧТО с ней связано; как она себя ведёт — говорит исходник. Символ,
который правишь или на который опираешься, читай телом целиком, а не по однострочной сводке.

Особенно с поведенчески-критичным кодом — миграции, повторы и откаты, слои совместимости,
конкурентные участки и пиннящие их тесты. Там читать настоящую реализацию и никогда не
передавать `compress_bodies:true`: он вырезает ровно те ветки, в которых риск.
